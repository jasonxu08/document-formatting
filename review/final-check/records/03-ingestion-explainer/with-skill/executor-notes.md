- **Step 3, two-zone layout.** `<!-- zone:human -->`, `<!-- zone:ai-input -->` and `<!-- zone:archive -->` markers; a "👤 START HERE - at a glance (for Priya and other new ingestion engineers)" heading; a "🗄️ Machine and archive zone - skip unless..." heading; lettered blocks A to D, each opening with an italic bin line. Graphviz PNG at 150 dpi, DOT beside it, viewed every PNG, made a downscaled 800 px copy to judge legibility, verbs on edges, one focal node (Catalog, blue), colour and shape meanings in the caption, alt text, edge lists with the backing sentence from the notes. - **Highlight budget.** Plain blockquote for the mental model, no `> [!NOTE]`, no HTML colour, bold only for labels and defined terms.
- **Honesty.** Everything that is not in the notes is marked ("my suggestion", "my sum", "My inference", "this page's labels") and listed in the ledger; where the notes disagree the page says which line it followed (section 6).
- **Deliver.** Images in `report.assets/`, relative forward-slash links, no machine-local paths (grepped for `Users` and drive letters), `check_doc.py` on both Markdown files (0 blockers, 0 majors, 0 minors each), a walk through the rubric's judgment rules, and a chat reply written as a panel in miniature.

## 2 Instructions that were unclear, contradictory, or that I did not follow

- **Sibling file versus "one doc for the wiki".** The skill moves machine material to a sibling file above about 60 lines "unless the user wants one self-sufficient file". The user said "a doc we can drop into the team wiki repo". I read that as not asking for a single file and followed the default (`report.evidence.md`). A wiki repo may list every `.md` as a page, so the sibling could be unwelcome. The skill gives no way to decide this.
- **Skeleton versus SKILL.md for explainers.** The skeleton is verdict-centred and puts the picture after the risk table; SKILL.md says mental-model sentence, then picture and list. I followed SKILL.md and used the skeleton only for the zone markers, panel shape and blocks A to D.
- **"Three to five path entries beat a full table of contents".** My doc has six numbered sections, so the path has seven entries (six sections plus the settings lookup). The panel budget did not bite, so I kept them all. It is unclear whether the cap is a rule or only a trimming order.
- **Glossary circularity (rubric B2).** Terms must be defined before the first numbered section that uses them, but section 1 (concepts and statuses) mentions Raw Zone, Schema Registry and others that section 2 defines. I used inline glosses and Figure 1 instead. It is unclear whether the glossary section is exempt.
- **Confidence without a verdict (E1).** E1 wants confidence on every judgment; an explainer has none. I added one Confidence line about source reliability. The skill does not say whether to include it.
- **D2 versus legibility.** D2 wants every participant in a diagram. Splitting into two figures means the Catalog appears in Figure 2 with only its Policy Engine edge. The skill says the overview's caption must say what it leaves out, but not what to do when a zoom view leaves out edges of a node it shows. I said so in Figure 2's caption.
- **"Write each fact once" versus pictures and numbered lists.** Section 3's numbered steps repeat what Figure 1 shows. The skill also says a diagram must not be the only carrier of information, so some overlap is by design, but I found no clean rule for how much.
- **Reading times.** The skill asks for "roughly how long" without a reading speed. I used 150 to 200 words a minute and recorded that in the ledger.
- **Chat reply format.** It asks for verdict, decisions and top risks. None apply to an explainer, so I gave the mental model, the one ask (Sam confirms seven points; date marked "suggested") and the two biggest source conflicts.
- **File names.** The task fixed `report.md`, and the skill derives `report.assets/` and `report.evidence.md` from the stem. A wiki would want a descriptive name; renaming means three names and the links between them. Block A says so.
- **800 px check.** "Look at the rendered file ... legible at about 800 px" has no tool for a faithful 800 px render. I downscaled with Pillow and looked at that.
- **Not followed on purpose:** `Next →` lines (order is obvious); the skeleton's verdict, decision and risk-table elements (nothing to judge); byte-exact copies in `<doc-stem>.data/` (no audit trail was asked for, so I recorded SHA-256 checksums of the two inputs in the evidence file instead); the full A4 handoff content in block A (A4 is for handoff documents, so I wrote a short maintenance block).
- **Not a skill instruction, but it shaped the result.** Today (2026-10-19) is itself a Monday, so "starts on Monday" probably means next Monday. I did not state Priya's start date anywhere.
- **Process incidents.** I tried to preview the rendered page in a browser. The tool blocked `file://` and timed out on screenshots, so I only checked table and list structure with markdown-it-py. While doing that, port 8765 was already served by another process (not mine); I requested its directory listing by mistake (file names only, no file content read) and did not touch that process. I deleted the `.playwright-mcp` log files my attempts created in the workspace root and every scratch file in the outputs folder.
